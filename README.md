# Web Practice

JavaScript、HTML・CSS、Web制作の基礎問題を、画面上で1問ずつ回答する学習アプリです。問題文を左のサイドに表示し、右側で回答・採点して次へ進みます。記述・選択問題は通常の回答欄、コード問題は言語に対応したTutorialKitのエディタを使います。スマホでは「問題」「解答」で切り替えます。回答・採点結果・途中の進捗を保存し、前の設問に戻って修正できます。

## ローカルで開く

Node.js 22以上を用意し、プロジェクトのフォルダで実行します。

```sh
npm ci
npm run dev
```

表示されたURLを開きます。回答・採点結果・進捗はブラウザーに保存されます。「回答を書き出す」でJSONを保存できます。`npm run build`で生成する`dist/preview/index.html`も単体で開けます。

## GASへ配置する

1. `npm run build`を実行します。
2. [Apps Script](https://script.google.com/)で新しいプロジェクトを作ります。
3. `dist/gas/`内の8ファイルを同じ名前で作成し、内容を貼り付けます。`.gs`はスクリプト、`.html`はHTMLとして作成します。`appsscript.json`はプロジェクト設定でマニフェストの表示を有効にして置き換えます。
4. エディターで`setup_`を一度実行します。問題データと回答を保存するスプレッドシートが作成されます。URLは実行ログに表示されます。
5. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選びます。実行するユーザーを自分にし、初回はアクセスできるユーザーも自分に設定してデプロイします。
6. 発行されたURLで回答・採点を試します。回答とブラウザーでの採点結果が`answers`シートに記録されます。

既存のスプレッドシートを使う場合は、スクリプトプロパティに`SPREADSHEET_ID`を設定してから`setup_`を実行します。再実行しても既存シートの内容は上書きしません。GASへの実際の配置と接続確認は、利用するGoogleアカウントで行ってください。

GASではHTML内にCSSとJavaScriptを埋め込んで配信します。開発時のファイル分割を維持したまま、ビルドでGASへ貼り付けられる構成にまとめています。参考画像と採点処理も同梱されます。

画面とコードの実行はブラウザー、問題の取得と回答の保存はGASが担当します。フォントはGoogle FontsからHTTPSで読み込みます。

## 問題を追加・編集する

GASでは「レッスン」と「設問」の2枚を編集します。「設問」は1行が1つの回答画面で、質問・選択肢・正解を同じ行に入力します。前段の説明は「レッスン」の導入文に残ります。

既存レッスンへの追加は、「設問」の空いている行に分野・レッスン番号・設問・回答形式・選択肢・正解を入力し、アプリを開き直します。選択肢と複数の正解はセル内改行で区切ります。IDと採点用JSONの入力は不要です。

ローカルでは `data/lessons.csv` と `data/questions.csv` を編集して `npm run build` で反映します。具体例とコード問題の追加方法は[問題の編集手順](docs/editing-questions.md)を参照してください。

旧構成のGASを更新する場合は、生成ファイルを差し替えて `setup_` を実行します。既存のシート内容から2枚の編集表へ移し、元のシートと回答記録を保持します。既に2枚の表がある場合は上書きしません。ローカルの移行前CSVは `data/archive/` に保存しています。

HTMLのstyle要素は、エディタではindex.htmlとstyle.cssに分けて表示します。両ファイルの編集内容を保存し、採点時に結合します。コード問題はエディタの下にプレビューを表示します。JavaScriptは「実行」、HTML/CSSは編集後に更新されます。表示結果を予想する問題では、参照コードだけを表示します。コードを編集して調べる実習は「コード」「プレビュー」で表示を切り替えます。

学習用の採点結果はブラウザーで計算し、GASへ保存します。JavaScriptはWorkerで実行し、CSSは通信とスクリプト実行を制限したiframeで描画します。画面・参考画像・採点プログラムを更新した場合は再ビルドし、GAS側のファイルを更新して新しいバージョンをデプロイします。

## ソースと確認

```text
src/            画面・データ検証・採点エンジン
vendor/         TutorialKitの画面・標準スタイルとライセンス
gas/           GASサーバーとマニフェストの原本
data/          編集用CSV
images/        問題の参考画像
scripts/       ビルドとローカル表示
tests/         採点・データ変換・保存処理のテスト
dist/gas/      GASへ配置する8ファイル
dist/preview/  単体で開けるHTML
forms.json     抽出時の元データ
```

```sh
npm test
npm run check:browser
npm run check:grading
npm run build
```

`npm run check:browser`で表示されるURLをブラウザーで開き、「検証する」を押すと、表示問題の解答例と誤答を実際に描画して検証します。検証ツールの実習では、本文・CSSの変更、回答の保存と復元、リセット後の再採点も検証します。結果は画面と一時フォルダ内の`results.txt`に出力します。

`npm run check:grading`は全設問について、正答・書式を変えた正答・空欄・初期コード・不正な選択などを検証します。表示されたURLで「検証する」を押すと、結果を画面と一時フォルダ内の`results.json`に出力します。

演習画面には[TutorialKit](https://github.com/stackblitz/tutorialkit)のナビゲーション、エディタ、標準テーマと左右の画面構成を使用しています。採点結果の表示とGASへの接続を組み込み、実行エンジンにはブラウザーのWorkerを使っています。DOM操作の採点には[LinkeDOM](https://github.com/WebReflection/linkedom)を使用しています。

TutorialKitはMITライセンスです。移植元と変更箇所は`vendor/tutorialkit/SOURCE.json`、配信するコードのライセンス本文はビルド時に生成する`THIRD_PARTY_NOTICES.md`を参照してください。問題文・画像・解答例・採点条件は`forms.json`、`data/`、`images/`に分けて管理します。
